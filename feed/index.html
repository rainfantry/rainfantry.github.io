// how this works

This feed runs on zero infrastructure. No server, no database, no cron job on a VPS. It uses GitHub Actions — a free automation layer built into GitHub — to scrape security data on a schedule and commit the result directly to the repository. The static page you're reading loads that file and renders it.

The sources

  • CISA KEV — CISA's Known Exploited Vulnerabilities catalogue. These are CVEs with confirmed in-the-wild exploitation. Highest priority.
  • NVD / CVE — NIST National Vulnerability Database API. Recent CVE disclosures with CVSS scores.
  • Hacker News — Algolia's public HN search API, filtered for security/exploit posts with engagement.
  • BleepingComputer — RSS feed. Reliable, human-written security news. No Cloudflare block on RSS.

The workflow

A GitHub Actions workflow (.github/workflows/scrape.yml) runs a Python script every 6 hours. The script fetches from each source, deduplicates, scores by recency and engagement, and writes a data.json file. It then commits and pushes that file back to the repo. GitHub Pages serves it statically.

# .github/workflows/scrape.yml (simplified)
on:
  schedule:
    - cron: '0 */6 * * *'   # every 6 hours
  workflow_dispatch:          # manual trigger anytime

jobs:
  scrape:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
      - run: pip install requests
      - run: python feed/scraper.py
      - run: |
          git config user.name "feed-bot"
          git config user.email "bot@users.noreply.github.com"
          git add feed/data.json
          git diff --staged --quiet || git commit -m "chore: update security feed"
          git push

Why this approach

Most "live" data sites need a backend server running 24/7. This one doesn't. GitHub Actions gives you 2,000 free minutes per month — more than enough to scrape 4 sources every 6 hours. The whole stack is: static HTML + JSON file + a scheduled script. Anyone can fork it and have their own live security feed in 5 minutes.
